# 06: 全域真实脏检查状态机、确定性保存顺序与离开守卫

**What to build:**
构建严密的全域真实未保存草稿状态机与全链路导航守卫体系。统一统合 `isBasicDirty`（基本设置字段深比对）与 `isRulesDirty`（规则数组深比对），得出 `hasUnsavedChanges`。同一 Flag 详情内切换 Tab 静默保留两个数据域的内存草稿并在 Tab 标题添加星号提示（如 `规则配置 *`），URL 同步更新 `?tab=...` 且不弹出误触弹窗。在 FlagHeader 点击“前往在线评估”时，若存在未保存草稿弹出三选一弹窗：【保存并前往】、【放弃修改并前往】、【继续留在本页编辑】。保存并前往严格按照“先基本设置、后规则配置”的确定性顺序执行；若出现部分成功部分失败（如基本设置成功但规则失败），就地更新成功实体并清除其脏标记，保留失败草稿，立即中止跳转停留在失败 Tab 并展示明确错误 Alert。存在未保存草稿离开 Flag（点击面包屑、侧边栏或浏览器后退）触发路由拦截，刷新或关闭网页触发浏览器原生 `beforeunload`。

**Blocked by:** 05: 规则批量同步、悬浮保存栏与清空草稿, 03: Flag 详情全屏工作台框架、Tab-Query 双向同步与基本设置域

## Answer
1. `isBasicDirty` 对基本设置字段做 JSON 深比对，`isRulesDirty` 走 `rulesEqual` 内容与次序深比对，二者合成 `hasUnsavedChanges`；改回服务端原值后对应脏状态自动消除。
2. 详情页内切换 Tab 只更新 `?tab=`，`basicDraft` 与 `rulesDraft` 静默保留，Tab 标题按脏状态追加 ` *` 星号；离开守卫只比较 `pathname`，因此切 Tab 不会被误拦。
3. 「前往在线评估」：无草稿直接跳转；有草稿弹出三选一 Modal（保存并前往 / 放弃修改并前往 / 继续留在本页编辑），并列出未生效数据域清单。
4. 「保存并前往」严格串行：先 `PUT /flags/:id` 保存基本设置，再 `PUT /flags/:id/rules` 保存规则。基本设置失败立即熔断并切到 `?tab=settings`；基本设置成功但规则失败时就地保留已生效实体、清除基本设置脏标记、保留规则草稿并切到 `?tab=rules`；两种情况都阻止跳转并展示明确错误 Alert。
5. 「放弃修改并前往」重置全部草稿后跳转；「继续留在本页编辑」只关闭弹窗，不发起请求。
6. 离开守卫：`useBlocker` 拦截面包屑、侧栏与浏览器后退（含 POP），弹出「离开当前 Flag？」确认；`beforeunload` 覆盖刷新与关闭窗口；保存请求进行中同样会被拦截。
