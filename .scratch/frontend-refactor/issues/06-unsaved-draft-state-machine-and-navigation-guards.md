# 06: 全域真实脏检查状态机、确定性保存顺序与离开守卫

**What to build:**
构建严密的全域真实未保存草稿状态机与全链路导航守卫体系。统一统合 `isBasicDirty`（基本设置字段深比对）与 `isRulesDirty`（规则数组深比对），得出 `hasUnsavedChanges`。同一 Flag 详情内切换 Tab 静默保留两个数据域的内存草稿并在 Tab 标题添加星号提示（如 `规则配置 *`），URL 同步更新 `?tab=...` 且不弹出误触弹窗。在 FlagHeader 点击“前往在线评估”时，若存在未保存草稿弹出三选一弹窗：【保存并前往】、【放弃修改并前往】、【继续留在本页编辑】。保存并前往严格按照“先基本设置、后规则配置”的确定性顺序执行；若出现部分成功部分失败（如基本设置成功但规则失败），就地更新成功实体并清除其脏标记，保留失败草稿，立即中止跳转停留在失败 Tab 并展示明确错误 Alert。存在未保存草稿离开 Flag（点击面包屑、侧边栏或浏览器后退）触发路由拦截，刷新或关闭网页触发浏览器原生 `beforeunload`。

**Blocked by:** 05: 规则批量同步、悬浮保存栏与清空草稿, 03: Flag 详情全屏工作台框架、Tab-Query 双向同步与基本设置域

**Status:** ready-for-agent

- [ ] 实现全域真实脏检查：`isBasicDirty` 比对基本设置字段，`isRulesDirty` 比对规则内容与次序，`hasUnsavedChanges = isBasicDirty || isRulesDirty`
- [ ] 仅当实际字段发生改变时才标记脏状态；若用户修改后又改回服务端原值，对应脏状态自动消除
- [ ] 同一 Flag 详情内切换 Tab（规则配置/变更历史/基本设置）静默保留所有草稿，Tab 标题根据脏状态动态显示星号徽标（如 `规则配置 *`、`基本设置 *`），URL Query 同步更新 `?tab=...` 且不弹出打扰确认
- [ ] Header 点击“前往在线评估”时，若存在未保存草稿，弹出三选一模态框，清晰告知未生效数据域清单
- [ ] 三选一弹窗选择【保存并前往】时，严格按照确定性顺序执行：**先提交基本设置 (`PUT /flags/:id`)，后提交规则配置 (`PUT /flags/:id/rules`)**
- [ ] 处理部分成功部分失败容错：
  - 若基本设置失败：立即中止后续流程，保留所有草稿，自动切换至 Tab 3（`?tab=settings`），阻止跳转并展示错误 Alert；
  - 若基本设置成功但规则配置失败：将已生效基本信息更新入 `savedFlag` 并清除 `basicDraft` 脏标记，保留未生效的 `rulesDraft`，自动切换至 Tab 1（`?tab=rules`），阻止前往评估跳转并弹出清晰错误 Alert；
  - 若全部成功：清除所有脏状态，平滑路由导航至 `/evaluations?flag_key=...&environment=...`
- [ ] 三选一弹窗选择【放弃修改并前往】：放弃所有本地草稿，重置为 `savedFlag` 状态并平滑导航至在线评估控制台
- [ ] 三选一弹窗选择【继续留在本页编辑】：关闭弹窗，不发起请求，停留在当前详情页
- [ ] 存在未保存草稿时，点击面包屑返回列表、点击全局侧栏菜单或点击浏览器后退，触发 React Router 离开确认弹窗拦截
- [ ] 存在未保存草稿时刷新或关闭浏览器窗口，触发浏览器原生 `beforeunload` 防误关确认提示
- [ ] 路由集成测试覆盖切 Tab 草稿留存、确定性串行保存、部分失败容错分支与离开拦截全量场景
