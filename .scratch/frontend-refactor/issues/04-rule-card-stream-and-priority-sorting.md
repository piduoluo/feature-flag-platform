# 04: 规则卡片流、数组顺序排序与只读兜底联动

**What to build:**
实现 Flag 详情的 Tab 1 规则配置工作台。以纵向卡片流形式展示当前 Flag 的全部匹配规则，卡片显示属性名、操作符（`equals`/`in`）、期望值与命中返回值，并依据卡片在草稿数组中的索引展示序号（01, 02...）。用户点击卡片上的“上移”或“下移”按钮，纯粹在本地内存中对调卡片数组元素位置，以数组相对次序作为执行优先级的唯一事实来源；首项禁用上移、末项禁用下移。若用户微调顺序后又恢复原状，脏状态自动复原。提供添加/编辑规则 Modal，追加末尾合法优先级并执行严格前端格式校验（`equals` 仅限标量，`in` 仅限非空标量 JSON 数组）。工作台底部固定展示只读的已生效默认返回值兜底卡片；若基本设置中存在未生效修改，渲染黄色警告徽标，强化生效与草稿差异认知。

**Blocked by:** 03: Flag 详情全屏工作台框架、Tab-Query 双向同步与基本设置域

**Status:** ready-for-agent

- [ ] Tab 1 规则配置工作台以纵向卡片流形式排布规则，卡片序号（01, 02...）严格根据本地草稿数组顺序渲染
- [ ] 每张卡片提供“上移”与“下移”操作按钮，点击仅在纯前端内存中对调数组元素位置；首张卡片禁用上移，末张卡片禁用下移
- [ ] 基于内容深比对实现脏检查：用户调整规则顺序后若又调回原顺序，`isRulesDirty` 自动复原为 false
- [ ] 点击“添加规则”或“编辑规则”弹出模态框，新增规则自动分配末尾下一个合法优先级序号
- [ ] 规则模态框对期望值执行严格前端校验：`equals` 仅允许输入标量（字符串、数字、布尔值）；`in` 仅允许输入非空标量 JSON 数组；格式错误时高亮提示并阻断确定
- [ ] 工作台底部固定渲染只读默认返回值兜底卡片，严格展示服务端已生效的 `savedFlag.default_value`（不提供编辑控件）
- [ ] 当 Tab 3 的 `basicDraft` 修改了默认返回值尚未保存时，兜底卡片右侧渲染黄色警告徽标（“基本设置中有未生效草稿”），杜绝草稿当生效配置误解
- [ ] 单元测试覆盖卡片数组顺序重排纯函数、`isRulesDirty` 脏检查及标量/数组格式校验器
- [ ] 路由集成测试覆盖卡片流展示、上下移内存交互、添加/编辑规则模态框及兜底卡片草稿徽标联动
