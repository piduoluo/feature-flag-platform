# 10: Flag Console 标题统计与工具栏层级优化

**Type:** task
**Status:** resolved
**Blocked by:** 08, 09

## Goal

在不改变既有业务流程和数据库结构的前提下，移除全局顶部面包屑，重排功能开关页面的标题、实时状态统计、环境筛选与操作工具栏，并通过现有列表接口的小型向后兼容扩展提供准确的状态统计和筛选。

## Acceptance

- [x] 所有页面不再显示全局顶部面包屑，页面标题仍位于内容区。
- [x] 桌面端不保留空白顶部栏；移动端只保留导航按钮。
- [x] 功能开关页使用唯一标题“功能开关管理”和指定辅助说明。
- [x] 标题右侧显示真实的全部、启用、停用统计，点击后按状态筛选。
- [x] `GET /api/v1/flags` 支持可选 `enabled` 参数并返回不受状态筛选影响的统计汇总。
- [x] 工具栏按环境在左、搜索/视图/刷新/新建在右排列，不增加独立筛选按钮。
- [x] 表格、卡片、分页、搜索、刷新、新建、复制、详情、评估与启停功能保持可用。
- [x] 后端、前端测试和构建通过，并完成桌面与窄屏真实页面验证。

## Answer

已完成 Flag 控制台的标题、状态统计与工具栏重排，并为现有列表接口补齐了向后兼容的状态统计与筛选能力；数据库结构和迁移未变。

**后端**

- `GET /api/v1/flags` 新增可选 `enabled=true|false` 查询参数；非法布尔值返回 `400 VALIDATION_ERROR`。
- 响应在原有 `items`、`total` 之外新增 `stats: { all, enabled, disabled }`。
- 统计与环境、搜索条件保持一致，但在应用 `enabled` 状态筛选之前计算，因此点击统计项筛选后三项数字保持稳定。
- Repository 使用一次聚合查询生成统计，再分别执行计数和分页查询；聚合的 `Select` 在克隆的 GORM statement 上执行，避免污染列表查询。

**前端**

- 移除 AppShell 的全局面包屑与桌面顶部栏；桌面内容从页面顶部开始，窄屏只保留导航按钮，且不恢复任何虚假用户入口。
- Flag 页使用唯一主标题「功能开关管理」和说明「管理各环境的功能开关，支持灰度发布与快速回滚。」。
- 标题右侧展示服务端返回的全部、启用、停用统计；数字约 36px、标签约 18px，项间使用浅色分隔线，当前项使用浅橙背景与品牌橙数字。
- 三项统计即状态筛选入口：点击写入 `?enabled=true|false`，列表由服务端筛选并回到第一页；不增加独立筛选按钮。
- 行内启停成功后同步修正统计数字；当前筛选状态与切换结果冲突时即时移除该行，避免统计和列表不一致。
- 工具栏左侧保留环境分段选择，右侧依次为搜索、列表/宫格视图切换、刷新和橙色「新建 Flag」；统一高度、圆角与描边，并与表格左右边缘对齐。
- 表格列宽按桌面可用宽度收敛，避免操作列被横向截断；窄屏仍使用原有容器内横向滚动和宫格视图。

**验证**

- 后端：`go build ./...`、`go vet ./...`、`go test -count=1 ./...`（连接 Compose 的真实 `feature_flag_test` 库）全部通过。
- 前端：`tsc --noEmit`、`vite build` 通过；13 个测试文件共 110 项测试通过。
- 真实服务：验证时 `/api/v1/flags` 返回 `{all: 8, enabled: 7, disabled: 1}`；`?enabled=true` 返回 7 条且统计保持不变；`?enabled=maybe` 返回 400。
- Playwright 真实浏览器 9 项冒烟测试通过，其中新增 2 项覆盖本票：标题/统计/无面包屑/状态筛选，以及 390px 窄屏下的导航按钮与全部工具栏操作。
- 已在 1440×900 与 390×844 真实页面核对桌面与窄屏布局。
