# 0002-atomic-audit-and-priority-integrity

## 上下文
系统要求规则评估具备确定性顺序，同一 Flag 下重复优先级必须有明确策略；同时要求同一次业务变更与历史写入必须保持原子一致。

## 决策
1. 规则优先级采用数字越小越优先（数值 1 为最高优先级）。
2. 同一 Flag 下拒绝重复优先级：业务层前置校验并拦截重复，同时在 PostgreSQL 建立 `UNIQUE (flag_id, priority)` 复合唯一索引物理兜底。
3. 业务变更与审计日志写入共用同一个数据库显式事务（Unit of Work），任何一方失败整体回滚。

## 原因与权衡
“数字越小越优先”符合自然优先级认知；相比运行时隐式二级排序，拒绝重复能在配置阶段消除歧义；单一事务提交从根本上杜绝了数据变更与审计日志不一致的隐患。
