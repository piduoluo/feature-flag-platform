# 0004-bulk-rule-sync-diff-audit-and-deployment

## 上下文
规则优先级调整存在临时冲突风险，且规则增删改需要留下精准的操作变更审计；同时交付方案需保证容器化环境一键稳定启动、无跨域阻碍且不产生脏数据。

## 决策
1. 规则管理采用 `PUT /api/v1/flags/:id/rules` 整体同步接口，在单数据库事务内比对原规则与新规则差异，精准计算新增、修改、删除明细，记录结构化变更历史，保证全成功或全回滚。
2. 历史审计日志弱关联 Flag，冗余存储 flag_key 与 environment。当前不提供删除 Flag 功能，避免引入过度设计的软删除逻辑。
3. Docker Compose 编排由 Nginx 作为单一生产 Web 入口反向代理后端 API；后端依赖 Postgres 健康检查，启动时自动执行 SQL 迁移（失败则终止启动）与幂等初始数据写入。

## 原因与权衡
批量同步结合比对差异，兼顾了避免唯一键冲突和产出精准可信审计日志的双重优势；单一入口与强健康检查保证评测时一次性开箱即用。
